# The Room Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** `/` opens on the sleeping operator's bedroom; clicking the main monitor (or Enter) zooms into it and the screen becomes the live shell; the vertical monitor zooms into `/napping`.

**Architecture:** The room is a layer in `/`'s own document, over the prerendered shell rows (ADR 0001 holds: the rows never leave the first response). By default the layer is a banner in normal flow (no JavaScript, narrow screens); an inline gate adds `html.room` before first paint on wide screens for a tab that has not entered yet, which turns the layer into a full-viewport overlay. Entering zooms the layer with a CSS transform, then removes `room`, sets `data-theme="dark"`, and only then adds `booting`, so the existing CSS boot schedule plays as the zoom lands. A 320×180 canvas over the still scene draws the ambient layer.

**Tech Stack:** TypeScript (node --test, tsc), esbuild client bundle, static assets on Cloudflare Workers assets, headless Chrome (playwright from the scratchpad) for visual checks.

**Spec:** `docs/superpowers/specs/2026-11-21-room-home-design.md`

## Global Constraints

- First paint ≤ 400 ms; the shell is live within the existing boot budget (≤ 1.5 s) **measured from entry**.
- The shell's prerendered rows stay in `/`'s HTML in every state (ADR 0001).
- Direct links (`/resume`, `/napping`, `/ops/...`, 404) are unchanged: no room there.
- Pixel rendering only: `image-rendering: pixelated`, no blur, no smoothing.
- Reduced motion: no zoom animation, no ambient motion; entering is a cut.
- Narrow = viewport narrower than 720 px **or** taller than wide: banner above a live shell, no zoom.
- Arriving through the room sets `data-theme="dark"` for the session; direct visits keep the system theme.
- Same session: once entered (`sessionStorage["lazie:entered"]`), `/` skips the room. `exit` in the shell zooms back out.
- No em or en dashes in visible copy. Hint copy names both the click and Enter.
- Scene coordinates (scene pixels, 320×180): main monitor x 255–286, y 80–100 (w 31, h 20); vertical monitor x 291–309, y 79–106 (w 18, h 27); cat sprite origin x 164, y 87, frame 23×18, 4 frames (rest, breath, tail, breath+tail); tower LEDs at (197,100) (197,104) (197,108) (206,100) (206,104) (206,112), the copy's at x − 28.
- Motion values: zoom 900 ms `cubic-bezier(.7,0,.2,1)`; breath cycle 2.4 s (raised for the second half); tail flick 0.3 s every 6.5 s; ambient tick 110 ms.

## Review Focus

1. **A visitor who enters, follows a link to `/resume`, presses `q`:** they land in the shell, not the room, and the theme is still dark.
2. **Window resized or rotated while the room is up:** crossing the narrow threshold must not leave a half-zoomed overlay; the banner and overlay must swap cleanly.
3. **Enter pressed while the shell input already has text** (after `exit` back to the room): Enter means "enter the room's monitor", not "submit the line".
4. **Screen reader on `/` with the room up:** the shell rows are still in reading order; the overlay image has one description; the two buttons are announced.
5. **Slow image load:** the room layer has fixed dimensions, so nothing shifts when `scene.png` arrives; until then the overlay shows the scene's background colour, not a blank white box.

Each line's test is added to the task that owns the code (marked "Review Focus n").
