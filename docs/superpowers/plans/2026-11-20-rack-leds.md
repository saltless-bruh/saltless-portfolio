# Rack LEDs Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** The rack LEDs show the telemetry state (live / stale / offline), defaulting to offline.

**Architecture:** `src/telemetry.ts` holds the state type and today's value. `src/mascot.ts` splits LED
pixels out of the rack paint into per-LED layers, writes `data-telemetry` on the SVG, and emits
state-scoped CSS: still forms outside the motion block, flicker/standby inside it.

**Tech Stack:** TypeScript on Node (`node --test`), inline SVG, CSS keyframes.

**Spec:** `docs/superpowers/specs/2026-11-20-rack-leds-design.md`

## Global Constraints

- Colour via token classes only (`m-muted`, `m-accent`); no hex, no inline `fill=`.
- Every running animation `step-end`; keyframes change opacity only; nothing animates outside
  `@media (prefers-reduced-motion: no-preference)`.
- `led-fault` (alarm red) must paint after every LED layer. Cat, idle, bubble, alarm timing unchanged.
- Standby: 1 s on / 1 s off. Flicker: deterministic from a fixed seed.

## Review Focus

- Art redrawn with no column lit in every unit → build must throw, not silently have no power LED (Task 1 test).
- An unknown `data-telemetry` value (client bug later) → falls back to the drawn pattern (stale look), never all-dark-and-still with no power (Task 1: still-frame default is the drawn pattern; offline is opt-in by attribute).
- Two activity LEDs with identical patterns → visible sync (Task 2 test).
- Alarm over live flicker → red layer must cover (paint order test, Task 1).
- Build-to-build drift of patterns → CSS must be byte-identical across calls (Task 2 test).

### Task 2: Live flicker and offline standby

**Files:** modify `src/mascot.ts`; test `test/mascot.test.ts`.

**Interfaces:**
- Consumes: `LEDS`, the `led<k>` classes from Task 1.
- Produces: `export function flickerPattern(seed: number, total: number): Span[]` (on-spans; uses `Span`) and CSS
  rules scoped `.mascot[data-telemetry="live"]` / `[data-telemetry="offline"]` inside the motion block.

- [ ] **Step 1: Failing tests:** `"live: activity LEDs flicker, each its own way"` — one `@keyframes` per activity LED,
  pairwise-distinct bodies; each pattern on ≥ 50% of its loop, with every off blip ≤ 0.3 s.
  `"offline: power LEDs blink in standby together"` — power LEDs share one `standby` animation of 2 s, on for the first half.
  `"LED patterns are the same on every build"` — `mascotCss() === mascotCss()` and `flickerPattern(1, 6)` equals itself.
  Existing "every animation steps" / reduced-motion tests unchanged.
- [ ] **Step 2:** `npm test` → FAIL.
- [ ] **Step 3: Implement.** Seeded PRNG (mulberry32); per activity LED a loop of 6 s alternating on segments
  0.3–1.4 s and off blips 0.08–0.25 s; keyframes via the existing `showDuring()`.
- [ ] **Step 4:** `npm test`, `npm run typecheck` → PASS/clean.
- [ ] **Step 5: Frame check** in headless Chrome: set `data-telemetry` to live and offline, pin a few times, screenshot the rack.
